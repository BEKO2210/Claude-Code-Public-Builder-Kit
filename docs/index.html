How it works

From one word to a working project.

The wizard is just the entry door. Here is what actually happens between "I have an idea" and "Claude is shipping code for me".

  1. 1

    One word in.

    You type something short — even a single phrase like "Training Plan App". No essay required, no forms to fill out, no jargon expected.

    Training Plan App
  2. 2

    The wizard sharpens it.

    Three short follow-up questions: who's it for, what should it do better, and is anything sparse — then a one-glance summary before generating. If you only typed one word, the wizard nudges you to add a little more.

    📱 An app
    For independent cafe owners
    Saves time on planning
    ✓
  3. 3

    12 documents are generated.

    Vision, roadmap, risks, architecture, marketing brief, prompts — all consistent with each other, all immediately useful. No TODO stubs, no placeholder paragraphs.

    📄 MASTERPLAN.md
    📄 ROADMAP.md
    📄 ARCHITECTURE.md
    📄 PROMPTS/initial.md
    + 8 more
  4. 4

    You sharpen the plan with Claude Code.

    Use Claude Code — in your browser via your GitHub repo, or in your terminal in the unzipped folder. Claude Code reads every file in the kit and can edit them directly. Each session iterates on one piece of the plan — Phase 1 / Step 1, then Step 2, then a risk you want to dig into. The plan stops being a stub and becomes the spec your project actually runs on.

    📂 12 files loaded from your repo
    Read MASTERPLAN.md and CLAUDE.md, walk me through Phase 1 / Step 1.
    Got it. First decision: are users tracking the same plan or each their own?
    Each their own. Add that to the masterplan.
  5. 5

    Claude builds autonomously.

    Once the plan is sharp, Claude executes against it — writes the code, runs the tests, reports back. You stay in the loop only on decisions, not on every line. The masterplan is the contract; Claude works it down phase by phase.

    claude
    › Reading MASTERPLAN.md…
    › Implementing Phase 1 / Step 2: data model.
    ✓ User entity + tests added (12 passing).
    ✓ Committed: feat(data) - user entity

Real output

This is what the kit gives you.

One snippet from a real generated MASTERPLAN.md for the idea "A SaaS dashboard for small business accountants". Browse the full 12-file output on GitHub.

MASTERPLAN.md ~280 lines · 1 of 12 files 
## 1. One-line summary

A SaaS dashboard for small business accountants who need to see month-end
status across all their clients without bouncing between five tools.

## 2. Audience

Small business accountants — typically firms of 1–10 partners managing
30–200 clients each. They are domain experts, not power users; first-run
flow has to make the daily core action obvious in under three minutes.

## 3. Domain-specific risks (professional services)

- Trust and credibility: a single embarrassing output destroys word-of-mouth.
  Slow rollout and a supervised mode beat a fast generic launch.
- Client-data privacy: assume PII and privileged information will end up
  in the system. No third-party logging, conservative retention, clear
  export + delete on request.
- Liability and expectation management: the product assists, it does not
  give legal / financial / tax / strategic advice…

For developers

Or run it locally.

Same tool, your machine. Two runtime dependencies (Express + archiver), no build step, MIT licensed.

git clone https://github.com/BEKO2210/Claude-Code-Public-Builder-Kit
cd Claude-Code-Public-Builder-Kit
npm install
npm start
# open http://localhost:5173

Or hit the API directly: 

curl -s -X POST https://claude-code-public-builder-kit.vercel.app/api/generate.zip \
  -H 'Content-Type: application/json' \
  -d '{"idea":"A SaaS dashboard for small business accountants"}' \
  -o kit.zip
